Fase 1 — Aquisicao (trafego e UTMs)
O usuario chega na LP via anuncio, organico, indicacao ou e-mail. Cada origem deve carregar UTMs para rastrear de onde veio a conversao.

Estrutura de UTMs recomendada

ParametroUsoExemplos
utm_sourceDe onde veio o trafegometa, google, youtube, instagram, email, indicacao
utm_mediumTipo de midiacpc, organic, social, email, referral
utm_campaignNome da campanhalancamento-jul26, reengajamento-q3, webinar-daniel
utm_contentVariacao do criativovideo-depoimento, carrossel-metodo, story-livro
utm_termPalavra-chave (search)vendas+whatsapp, metodo+redrive

Exemplos de URLs com UTMs

redpower.redrive.com.br?utm_source=meta&utm_medium=cpc&utm_campaign=lancamento-jul26&utm_content=video-depoimento

redpower.redrive.com.br?utm_source=email&utm_medium=email&utm_campaign=reengajamento-q3

redpower.redrive.com.br?utm_source=indicacao&utm_medium=referral&utm_campaign=programa-afiliados&utm_content=link-carlos

Dados capturados na chegada

UTMs completas → Cookie + Backend Atribuicao de conversao — saber qual campanha gerou a venda
Referrer → Backend Fallback quando nao ha UTM — identifica origem organica
Device / Browser → Analytics Otimizar experiencia por dispositivo (mobile vs desktop)
Timestamp de entrada → Analytics Calcular tempo ate conversao e janelas de retargeting
fbclid / gclid → Cookie + Backend Conversao API do Meta/Google — atribuicao server-side
Implementacao: Salvar UTMs em cookie de 1a parte (30 dias) no primeiro acesso. Se o usuario voltar sem UTMs, manter os originais (first-touch). Enviar junto com o pedido no checkout para atribuicao correta.
Fase 2 — Landing Page (engajamento)
O usuario navega a LP, le as secoes, interage com FAQ e pricing. Cada interacao e um sinal de intencao.

Eventos a rastrear na LP

Scroll depth (25/50/75/100%) → GA4 + Meta Pixel Medir interesse — quem rolou 75%+ e audiencia quente pra retargeting
Clique em CTA (qual botao) → GA4 + Meta Pixel Identificar qual secao converte mais e otimizar posicionamento
Visualizacao secao Pricing → GA4 + Meta Pixel Evento de "ViewContent" — audiencia com intencao de compra
Abertura de FAQ → GA4 Identificar duvidas mais frequentes para otimizar copy
Clique no card RedMax Revisao → GA4 + Meta Pixel Sinal de que o usuario ja e cliente Redrive — segmentacao
Tempo na pagina → GA4 Correlacionar com conversao — tempo ideal vs bounce
Meta Pixel — eventos recomendados: PageView (automatico), ViewContent (secao Pricing), AddToCart (clique em CTA de plano), InitiateCheckout (abriu checkout), Purchase (pagamento confirmado). Enviar valor e moeda em cada evento pra otimizar campanhas por ROAS.
Fase 3 — Checkout e pagamento
O usuario escolheu um plano e inicia o processo de compra. Aqui mora a maior perda de conversao — cada campo e cada segundo conta.

Dados coletados no checkout

Nome completo → Backend + Redrive (CRM) Identificacao do aluno e personalizacao
E-mail → Backend + Redrive (CRM) + E-mail mkt Login, comunicacao, sequencias automaticas
Telefone (WhatsApp) → Backend + Redrive (CRM) Onboarding RedMax, suporte, reengajamento
CPF/CNPJ → Gateway + NF Emissao de nota fiscal e antifraude
Endereco de entrega → Backend + Logistica Envio dos livros fisicos (todos os planos)
Plano escolhido → Backend + Redrive (CRM) Definir acesso, elegibilidade de upsell, segmentacao
Forma de pagamento → Gateway Processar cobranca (cartao ate 6x, Pix, boleto)
UTMs (do cookie) → Backend Vincular venda a origem — atribuicao de conversao
Upsell aceito? (order bump) → Backend + Redrive (CRM) Se RedUp aceitou upgrade para RedMax no checkout

Fase 4 — Pos-compra (ativacao)
O usuario pagou. Agora precisa ser ativado — acessar a plataforma, assistir a primeira aula, interagir com o agente.

Sequencia de e-mails e dados enviados

E-mail 1: Boas-vindas (0h) → E-mail mkt Link de acesso, credenciais, sem upsell — foco em ativar
E-mail 2: Primeira aula (24h) → E-mail mkt Verificar se ja acessou; se nao, reforcar o link
E-mail 3: Dica + Upsell (7d) → E-mail mkt "Ja comecou a aplicar? Conheca a Implantacao" (se RedUp)
E-mail 4: Meio do curso (14d) → E-mail mkt Baseado no progresso real — se parou na aula 3, reengajar
E-mail 5: Conclusao → E-mail mkt Parabens + CTA forte para Implantacao (se RedUp)
Dado essencial para e-mails inteligentes: O backend precisa expor o progresso do aluno (qual aula esta, % assistido) para a ferramenta de e-mail. Sem isso, todos recebem a mesma sequencia generica. Com isso, quem parou na aula 3 recebe "Voce parou na Janela de Atencao — e uma das mais importantes".
Fase 5 — Plataforma do aluno (consumo)
O aluno acessa /metodo, assiste aulas, interage com o agente, faz anotacoes. Cada interacao gera dados que precisam ser persistidos.

Dados de video e progresso

Posicao do video (segundos) → Backend (API) Retomar de onde parou em qualquer dispositivo
% assistido por aula → Backend (Analytics) Metricas de consumo — identificar aulas com abandono
Aula marcada como concluida → Backend (API) Progresso do curso, trigger de e-mails, elegibilidade de upsell
Vezes que abriu cada aula → Backend (Analytics) Revisitas indicam conteudo valioso — informar producao

Dados de chat com o agente

Mensagens do usuario → Backend (API) Historico persistente — nunca perder, mesmo ao reassistir
Gatilhos disparados → Backend (API) Saber quais triggers o aluno ja recebeu em cada sessao
Respostas a gatilhos → Backend (Analytics) Taxa de engajamento — gatilhos que geram conversa vs ignorados
Mensagens salvas como nota → Backend (API) Conteudo que o aluno considerou valioso o suficiente para anotar
Modo de uso (sidebar vs fullscreen) → Backend (Analytics) Otimizar UX — qual interface e mais usada

Dados de notas

Titulo + conteudo da nota → Backend (API) Persistir entre sessoes e dispositivos
Marcador (importante/ideia/acao/duvida) → Backend (API) Categorizacao das notas pelo aluno
Ordem das notas → Backend (API) Manter organizacao personalizada do aluno
Quantidade por tipo → Backend (Analytics) Alunos que anotam "acao" estao mais propensos a implementar
Fase 6 — Analytics e inteligencia
Todos os dados de uso alimentam dashboards internos para decisoes de produto, marketing e CS.

Metricas de negocio derivadas

Taxa de ativacao → Dashboard admin % de compradores que acessaram a plataforma em 48h
Taxa de conclusao do curso → Dashboard admin % que completou as 8 aulas — correlacionar com upsell
Tempo medio ate conclusao → Dashboard admin Calibrar sequencia de e-mails e timing de upsell
Engajamento por aula → Dashboard admin Aulas com abandono = conteudo a melhorar
Conversao de upsell → Dashboard admin % de RedUp que fizeram upgrade para RedMax/Implantacao
CAC por canal (UTM) → Dashboard admin Custo de aquisicao por utm_source — otimizar investimento
LTV por plano → Dashboard admin Valor total do cliente incluindo upsells — justificar CAC
Fase 7 — Upsell e retencao
Com os dados de uso, o sistema decide quando e como oferecer upgrades.

Mapa de destino dos dados

Cada sistema recebe dados especificos. Nenhum dado deve ficar apenas em localStorage em producao.

Backend / Banco de dados (Supabase ou equivalente)

  • Perfil do usuario (nome, e-mail, telefone, plano, data de compra)
  • Progresso do curso (posicao de video, aulas concluidas, timestamps)
  • Historico de chat completo (mensagens do usuario + gatilhos, por aula, por sessao)
  • Notas (titulo, conteudo, marcador, ordem, por aula)
  • UTMs da aquisicao (vinculadas ao usuario)
  • Dados de uso/analytics (eventos, heartbeats, metricas agregadas)

Gateway de pagamento (Stripe / Pagar.me)

  • Dados de cobranca (cartao tokenizado, Pix, boleto)
  • Historico de transacoes e status
  • Webhooks de confirmacao/cancelamento/estorno

Redrive (CRM)

Os contatos ja existem dentro da Redrive — o fluxo atualiza registros existentes, nao cria novos.

  • Contato ja existente atualizado com plano comprado + data + valor
  • UTMs da aquisicao vinculadas ao contato (para segmentacao de campanha)
  • Status atualizado: ativo, concluiu curso, fez upgrade, inativo
  • Score de engajamento (derivado dos dados de uso)
  • Historico de interacoes com o RedPower registrado no contato

Ferramenta de e-mail (ActiveCampaign, Resend, etc.)

  • E-mail + nome + plano (para segmentacao)
  • Tags: "concluiu-curso", "parou-aula-3", "elegivel-revisao"
  • Progresso do curso (via webhook do backend) para e-mails contextuais

Analytics (GA4 + Meta Pixel)

  • Eventos de LP: PageView, ViewContent, scroll, cliques em CTA
  • Eventos de checkout: InitiateCheckout, Purchase (com valor)
  • fbclid / gclid para Conversions API (server-side)
  • Audiencias de retargeting: visitou LP, clicou pricing, abandonou checkout

Logistica (envio de livros)

  • Endereco de entrega + nome do destinatario
  • Plano (define quais livros enviar — todos os planos enviam fisico)
  • Codigo de rastreio → e-mail para o aluno

Conversions API (server-side tracking)

Com o fim dos cookies de terceiros, rastrear conversoes apenas pelo pixel do navegador perde eficacia. A Conversions API (CAPI) envia eventos do servidor diretamente para Meta e Google, garantindo atribuicao mesmo com bloqueadores.
